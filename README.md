# Mini NPU Simulator

## 1. 프로젝트 소개

이 프로젝트는 작은 NPU(Neural Processing Unit)의 연산 방식을 흉내 내는 Python 기반 콘솔 프로그램이다.

두 개의 필터(Cross, X)와 입력 패턴 사이의 MAC(Multiply-Accumulate) 연산 점수를 계산하고, 점수를 비교하여 입력 패턴을 판별한다.

실제 NPU 하드웨어를 사용하는 것이 아니라, CPU에서 중첩 반복문으로 MAC 연산을 구현하여 NPU의 기본적인 계산 원리를 시뮬레이션한다.

## 2. 개발 환경

- Python 3.11.6
- Visual Studio Code
- 외부 라이브러리 사용 없음
- Python 표준 라이브러리 사용

## 4. 실행 방법

프로젝트 폴더에서 다음 명령어를 실행한다.

```bash
python main.py
```

실행 메뉴:

1. 사용자 입력 모드
2. JSON 분석 모드
0. 종료

### 사용자 입력 모드

- 3×3 필터 A와 B를 입력한다.
- 3×3 입력 패턴을 입력한다.
- 각 필터와 패턴의 MAC 점수를 계산한다.
- 두 점수를 비교하여 A 또는 B를 판정한다.
- 연산 시간과 성능 분석 결과를 출력한다.
- 입력 행의 숫자 개수나 숫자 형식이 잘못되면 재입력을 요청한다.

### JSON 분석 모드

- `data.json` 파일을 읽는다.
- 5×5, 13×13, 25×25 패턴을 분석한다.
- 패턴 ID에서 행렬 크기를 추출하고 해당 크기의 필터를 선택한다.
- 행렬 크기와 숫자 형식을 검증한다.
- 계산 결과와 정답을 비교하여 PASS 또는 FAIL을 출력한다.
- 전체 테스트 결과와 크기별 성능을 출력한다.

## 5. 핵심 구현 내용

### MAC 연산

MAC은 Multiply-Accumulate의 약자로, 행렬의 같은 위치에 있는 값을 곱한 뒤 모든 결과를 누적하여 더하는 연산이다.

```python
def mac(filter_matrix, input_matrix):
    size = validate_matrix(filter_matrix, "필터")
    input_size = validate_matrix(input_matrix, "입력 패턴")

    if size != input_size:
        raise ValueError("행렬 크기가 다릅니다.")

    score = 0.0

    for row in range(size):
        for col in range(size):
            score += (
                filter_matrix[row][col]
                * input_matrix[row][col]
            )

    return score
```

외부 라이브러리 없이 중첩 반복문을 사용하여 MAC 연산을 구현했다.

간단한 2×2 행렬 계산 예시는 다음과 같다.

```text
필터:
1 0
0 1

입력:
2 3
4 5

계산:
(1 × 2) + (0 × 3) + (0 × 4) + (1 × 5)

결과:
2 + 0 + 0 + 5 = 7
```

같은 위치의 원소끼리 곱한 후 누적 합산하여 최종 점수를 반환한다.

### 판정 로직

- Cross 점수가 더 크면 Cross로 판정한다.
- X 점수가 더 크면 X로 판정한다.
- 두 점수의 차이가 EPSILON보다 작으면 UNDECIDED로 판정한다.

```python
EPSILON = 1e-9
```

부동소수점 연산에서는 계산 과정에서 미세한 오차가 발생할 수 있다. 따라서 두 점수가 완전히 같은지만 비교하지 않고 허용 오차를 적용했다.

`1e-9`는 이번 프로젝트의 점수 비교에 사용하는 작은 허용 오차 기준이다. 입력값과 계산 정밀도에 따라 허용 오차를 조정할 수 있으며, 지나치게 크게 설정하면 실제로 다른 점수도 동점으로 처리될 수 있다.

### 라벨 및 필터 키 정규화

JSON 데이터에서는 같은 의미의 라벨이 서로 다른 형태로 표현될 수 있다.

| 입력 표기 | 표준 라벨 |
|---|---|
| `+` | Cross |
| `cross` | Cross |
| `Cross` | Cross |
| `x` | X |
| `X` | X |

필터 키도 대소문자와 표기 차이로 인해 데이터를 찾지 못하는 상황이 발생할 수 있다.

따라서 필터 키를 조회하기 전에 문자열을 정리하고 소문자로 변환하여 표준 키인 `cross` 또는 `x`로 통일하는 방식으로 처리한다.

정규화 과정에서는 앞뒤 공백도 제거한다. 지원하지 않는 키는 임의로 다른 필터에 연결하지 않고 오류로 처리한다.

### 정규화 함수를 분리한 이유

`normalize_label()`을 별도 함수로 분리한 이유는 라벨 변환 로직을 한곳에서 관리하기 위해서다.

이렇게 하면 다음과 같은 장점이 있다.

1. 사용자 입력이나 JSON 데이터 등 여러 위치에서 같은 변환 규칙을 재사용할 수 있다.
2. 라벨 규칙이 변경되어도 한 함수만 수정하면 된다.
3. 변환 결과를 독립적으로 테스트할 수 있다.
4. 판정 로직과 문자열 변환 로직을 분리하여 코드의 가독성을 높일 수 있다.

필터 키 정규화 역시 별도의 처리 함수로 관리하면 필터 데이터의 표기 방식이 달라져도 일관되게 대응할 수 있다.

### JSON 데이터 처리

- 패턴 ID에서 정규표현식으로 행렬 크기를 추출한다.
- 추출한 크기에 맞는 필터를 선택한다.
- 필터 키와 정답 라벨을 표준 형식으로 정리한다.
- 행렬의 크기와 숫자 형식을 검증한다.
- 잘못된 패턴 ID나 필터 데이터가 있으면 해당 케이스를 실패 처리한다.
- 오류가 발생해도 나머지 케이스의 분석을 계속 진행한다.

현재 지원하는 패턴 ID 형식은 `size_N_번호`이다.

형식이 다른 패턴 ID는 임의로 추측하지 않고 오류 사유를 출력한다. 새로운 패턴 형식을 지원하려면 정규표현식과 크기 검증 규칙을 함께 수정해야 한다.

현재 JSON 테스트에서는 모든 패턴이 명확하게 판정되어 6개 모두 PASS로 처리되었다.

### 성능 측정 범위

성능 측정은 `average_mac_time()` 함수에서 `time.perf_counter()`를 사용하여 시작과 종료 시각을 기록하는 방식으로 구현했다.

측정 대상은 다음과 같다.

- MAC 함수 호출
- 입력 행렬과 필터의 유효성 검증
- 중첩 반복문을 이용한 곱셈 및 누적 합산

다음 작업은 측정 구간에 포함하지 않는다.

- 사용자 키보드 입력
- JSON 파일 읽기
- 콘솔 출력
- 결과 화면 표시

따라서 측정값은 프로그램 전체 실행 시간이 아니라 MAC 함수 호출 구간의 평균 시간이다.

## 8. 시간 복잡도 분석

MAC 연산은 행렬의 모든 원소를 한 번씩 확인한다.

N×N 행렬을 기준으로 계산하면 총 연산 횟수는 다음과 같다.

```text
N × N = N²
```

따라서 시간 복잡도는 O(N²)이다.

| 행렬 크기 | 연산 횟수 |
|---|---:|
| 3×3 | 9 |
| 5×5 | 25 |
| 13×13 | 169 |
| 25×25 | 625 |
| 1000×1000 | 1,000,000 |

행렬 크기가 커질수록 연산 횟수가 제곱에 비례하여 증가한다.

이론적으로 연산량은 N²에 비례하지만 실제 실행 시간은 CPU 성능, Python 반복문 처리 비용, 메모리 접근 및 시스템 부하에도 영향을 받는다. 따라서 실제 측정 시간이 이론적인 연산 횟수와 완전히 같은 비율로 증가하지는 않는다.

### 대규모 행렬 처리 시 고려 사항

1000×1000 행렬은 원소가 1,000,000개이므로 3×3 행렬보다 훨씬 많은 연산과 메모리를 요구한다.

특히 Python의 리스트와 숫자 객체는 원소 값 외에도 객체 관리에 필요한 메모리를 사용한다. 입력 행렬과 두 필터를 동시에 메모리에 유지하면 메모리 사용량도 증가한다.

대규모 행렬을 처리할 때는 다음과 같은 최적화를 고려할 수 있다.

1. 행렬 전체를 한 번에 처리하는 대신 블록 단위로 나누어 처리한다.
2. 불필요한 행렬 복사와 임시 객체 생성을 줄인다.
3. 반복문과 데이터 접근 구조를 최적화한다.
4. 실제 병렬 연산이 필요한 경우 NumPy, C/C++ 또는 GPU/NPU 기반 연산 환경을 검토한다.

현재 프로젝트는 외부 라이브러리 없이 Python 중첩 반복문으로 구현한 기본 시뮬레이터이므로 1000×1000 처리 성능을 실제로 측정한 것은 아니다. 위 내용은 대규모 처리 시 예상되는 기술적 고려 사항이다.

## 9. CPU와 NPU의 연산 방식 비교

현재 프로그램은 CPU에서 MAC 연산을 순차적으로 실행한다.

### CPU 방식

- 일반적인 CPU 프로그램은 반복문에 따라 원소를 순차적으로 계산한다.
- 범용적인 작업을 처리하는 데 적합하다.
- 행렬 크기가 커지면 반복 횟수와 메모리 접근 비용이 증가한다.
- Python으로 작성한 중첩 반복문은 인터프리터 실행 비용도 발생한다.

### NPU 방식

- NPU는 인공지능 연산을 효율적으로 수행하도록 설계된 전용 프로세서다.
- 다수의 곱셈과 누적 연산을 병렬로 처리할 수 있도록 설계된다.
- 행렬 연산을 위한 전용 연산 장치와 데이터 이동 구조를 활용한다.
- 병렬 연산이 가능하더라도 데이터 이동, 메모리 대역폭, 작업 분할 및 장치 활용률이 병목이 될 수 있다.

### 병목 요인 비교

| 구분 | CPU 기반 처리 | NPU 기반 처리 |
|---|---|---|
| 연산 방식 | 일반적으로 순차 처리, 일부 병렬 처리 지원 | 다수의 연산을 병렬 처리하도록 설계 |
| 주요 병목 | 반복문 실행 비용, 메모리 접근 | 메모리 대역폭, 데이터 이동, 장치 활용률 |
| 장점 | 범용성 및 유연성 | AI 행렬 연산의 높은 병렬 처리 효율 |
| 고려 사항 | 연산량 증가에 따른 실행 시간 증가 | 데이터 준비 및 장치 전송 비용 |

NPU가 항상 모든 작업에서 CPU보다 빠른 것은 아니다. 작은 행렬이나 데이터 전송 비용이 큰 작업에서는 NPU의 병렬 처리 장점이 충분히 나타나지 않을 수 있다.

이번 프로젝트는 실제 CPU와 NPU의 속도를 직접 비교하는 벤치마크가 아니라, MAC 연산의 구조와 계산량을 이해하기 위한 시뮬레이터다.

## 10. 라벨 확장 및 유지보수 방법

새로운 판정 라벨을 추가하려면 다음 순서로 수정해야 한다.

1. `normalize_label()`에 새로운 입력 표기와 표준 라벨을 추가한다.
2. 필터 키 정규화 함수에도 새로운 필터 키를 연결한다.
3. JSON 데이터에 새 필터 행렬을 추가한다.
4. 판정 함수에서 새 라벨을 선택할 수 있도록 비교 로직을 확장한다.
5. 새 라벨이 정답인 테스트 패턴을 `data.json`에 추가한다.
6. 정상 입력, 잘못된 라벨, 점수 동점 상황을 각각 테스트한다.
7. README의 라벨 표와 테스트 결과를 갱신한다.

라벨 변환, 필터 선택, 점수 판정 로직을 분리해 두면 새로운 유형이 추가되더라도 수정 범위를 명확하게 관리할 수 있다.

## 11. 오류 및 예외 처리

프로그램의 안정성을 위해 다음 항목을 검증했다.

1. 입력 행렬의 행과 열 개수가 맞지 않는 경우
2. 숫자가 아닌 값이 입력된 경우
3. `nan`, `inf` 등 유효하지 않은 숫자가 입력된 경우
4. 행렬 크기가 필터와 일치하지 않는 경우
5. JSON 파일이 존재하지 않는 경우
6. JSON 데이터 형식이 잘못된 경우
7. 필수 필터 또는 패턴 데이터가 누락된 경우
8. 잘못된 사용자 입력에 대해 재입력을 요청하는 경우
9. 특정 테스트 케이스에서 오류가 발생해도 나머지 케이스를 계속 분석하는 경우
10. 점수가 같거나 허용 오차 이내인 경우 UNDECIDED로 판정하는 경우

오류가 발생한 경우 가능한 범위에서 해당 패턴 ID와 오류 원인을 출력하여 문제를 확인할 수 있도록 했다.
